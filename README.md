# StorePrice

Android-приложение для небольшого продуктового магазина: общий каталог товаров, цены в тенге, поиск, сканирование штрихкодов, история цен, офлайн-доступ и синхронизация между сотрудниками.

## Текущее состояние

**Этапы 2–4 реализованы и проверены на физическом телефоне.** Работает локальный каталог на Room, сканер CameraX + ML Kit, вход по номеру телефона и паролю, общий каталог Supabase и запись через RPC с контролем версии. Пользователь подтвердил успешный вход, общий каталог, запись через RPC и офлайн-режим на своём телефоне. Debug APK собирается, 116 тестов и lint проходят.

Экран сканера, запрос/отказ в разрешении, открытие камеры и её освобождение при выходе проверены на эмуляторе Android 15. Полная матрица форматов, автофокус, освещение и отзыв разрешения отдельно не проверялись.

**Этап 5 реализован локально.** После первого снимка каталог обновляется инкрементально по курсору `updated_at`, а не скачивается целиком. Supabase Realtime запускает ту же синхронизацию при активном приложении; при восстановлении сети и ручном обновлении каталог догоняет изменения. В каталоге есть индикатор сети, время последней успешной синхронизации и кнопка обновления; при офлайне показываются сохранённые данные с предупреждением. Чтение повторяется с ограниченным экспоненциальным backoff, записи из UI автоматически не повторяются. Для Realtime подготовлена миграция `004_realtime.sql`, но к живому проекту она ещё не применена; живая проверка двух устройств впереди. Инструкция — [`docs/SUPABASE_SETUP.md`](docs/SUPABASE_SETUP.md).

Подробности: [`CURRENT_STATUS.md`](CURRENT_STATUS.md).

## Возможности

### Каталог

- каталог товаров с ценой в целых тенге;
- поиск по названию и штрихкоду без учёта регистра и лишних пробелов;
- приоритет точного штрихкода и точного названия;
- добавление и редактирование с валидацией;
- уникальность штрихкода среди активных товаров, ведущие нули сохраняются;
- удаление с подтверждением (логическое, с возможностью переиспользовать штрихкод);
- локальное хранение в Room, данные сохраняются после перезапуска;
- русский интерфейс на Compose Material 3.

### Общий каталог (этап 4)

- начальная синхронизация общего каталога Supabase в Room;
- Room остаётся источником данных для списка, поиска, карточки и сканера;
- создание, изменение и удаление через серверные RPC с контролем `version`;
- история цены и аудит пишутся серверными триггерами;
- повторное использование штрихкода после логического удаления;
- ошибки дубликата, конфликта версий, офлайна и сервера различаются в форме;
- при офлайне редактирование скрыто, а введённые значения не теряются при ошибке сохранения;
- legacy-товары из Room один раз выгружаются в общий каталог при первом входе.

### Синхронизация и офлайн (этап 5)

- первый успешный sync заменяет локальный снимок, последующие читают только строки с `updated_at >=` сохранённого курсора;
- курсор и время последней успешной синхронизации хранятся в приватном `SharedPreferences`, Room schema не менялась;
- Supabase Realtime при активном приложении запускает инкрементальную синхронизацию; события Realtime не доверяются напрямую, данные всегда перечитываются через PostgREST и RLS;
- при восстановлении сети выполняется автоповтор, а после возврата в foreground Realtime переподключается;
- индикатор сети, время последней синхронизации, состояние «Обновление…» и кнопка ручного обновления в каталоге;
- при офлайне показываются сохранённые данные с предупреждением, что цены могут быть устаревшими;
- чтение каталога повторяется с ограниченным экспоненциальным backoff; записи из UI автоматически не повторяются, чтобы не создавать дубликаты;
- миграция `004_realtime.sql` добавляет `products` в publication `supabase_realtime`; её нужно применить отдельным шагом.

### Вход (этап 4)

- вход по номеру телефона и паролю через Supabase Auth;
- нормализация казахстанских/российских номеров к E.164;
- восстановление сессии и автоматический refresh;
- проверка активного профиля сотрудника на сервере;
- неактивный профиль разлогинивает пользователя;
- офлайн-вход по свежему кэшу активного профиля (до 30 дней) с баннером «Нет связи»;
- тихая проверка сессии при возврате приложения на передний план;
- выход из меню аккаунта;
- русские сообщения об ошибках входа;
- токены — в приватных `SharedPreferences`, backup отключён.

### Сканер

- CameraX-предпросмотр и рамка наведения;
- ML Kit на устройстве: EAN-13, EAN-8, UPC-A, UPC-E, Code 128, Code 39, Code 93, ITF, Codabar;
- запрос разрешения камеры, обработка отказа и отсутствия камеры;
- защита от повторной обработки одного кода за сессию;
- найденный активный товар открывает карточку;
- неизвестный код открывает форму нового товара с заполненным штрихкодом;
- камера останавливается при уходе с экрана.

## Быстрый старт

```bash
source scripts/android-env.sh
./gradlew assembleDebug
./gradlew testDebugUnitTest
./gradlew lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Для входа нужны локальные публичные параметры Supabase в `local.properties` (файл исключён из Git):

```properties
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_ANON_KEY=<publishable-key>
```

`SUPABASE_URL` — базовый адрес без `/rest/v1/`. `service_role` в Android-модуль не добавляется. Без этих параметров приложение собирается, но показывает сообщение о незавершённой настройке.

Установка на подключённый телефон или эмулятор:

```bash
adb devices -l
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.storeprice.app/.MainActivity
```

## Ограничения

- На физическом телефоне подтверждены основной сценарий сканера (распознавание, добавление товара, повторное открытие карточки) и основной сценарий этапа 4 (вход, общий каталог, запись через RPC, офлайн-режим). Не проверены отдельно все форматы на разных упаковках, автофокус, слабое освещение, блики, отзыв разрешения и отсутствие камеры; модель устройства не зафиксирована.
- Экран сканера и lifecycle камеры проверены на эмуляторе Android 15 (AVD `storeprice_test`); эмулятор не заменяет проверку реального распознавания.
- Нет instrumented/Compose UI-тестов: клики, разрешения и навигация проверены вручную.
- Серверная схема истории цен подготовлена, но UI истории и восстановления удалённых товаров не реализованы.
- Живая проверка Realtime на двух устройствах, индикатора сети, времени синхронизации, перезапуска без сети и возврата сети на APK `0.5.0` ещё впереди.
- Для Realtime нужно применить `004_realtime.sql` к живому проекту; без этого публикация `products` не отправляет события.
- WorkManager, фоновая синхронизация и очередь офлайн-записей не реализованы. Записи из UI автоматически не повторяются; при потере ответа ручной повтор создания товара без штрихкода может дать дубликат.
- Первая синхронизация выгружает legacy-товары из Room; локальный UUID передаётся на сервер как `p_id`, поэтому идентификатор сохраняется, а повторная выгрузка не создаёт дубликат. Для не-UUID локальных записей (если такие появятся) сервер выдаст новый `id`.
- Живой Supabase настроен: миграции `001`/`002` применены, `003_hardening.sql` и `004_realtime.sql` ожидают отдельного применения; Phone provider включён, публичная регистрация отключена, первый администратор создан.
- Деактивация сотрудника, смена роли и принудительный refresh через живой JWT ещё не проверены.
- Токены хранятся в приватных `SharedPreferences` без отдельного шифрования; backup отключён.
- Release-подпись и minify не настроены.
- Lint предупреждает о доступных новых версиях зависимостей; обновление не выполнялось, чтобы не менять проверенный toolchain без отдельной задачи.
