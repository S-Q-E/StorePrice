# Тестирование StorePrice

## Команды

```bash
source scripts/android-env.sh
./gradlew testDebugUnitTest
./gradlew lintDebug
```

Полная чистая проверка:

```bash
./gradlew clean assembleDebug testDebugUnitTest lintDebug
```

Отчёты:

- тесты: `app/build/reports/tests/testDebugUnitTest/index.html`
- lint: `app/build/reports/lint-results-debug.html`
- XML-результаты: `app/build/test-results/testDebugUnitTest/`

Один класс:

```bash
./gradlew testDebugUnitTest --tests 'com.storeprice.app.ui.scanner.ScannerViewModelTest'
```

## Что покрыто

### Каталог

- Создание товара с названием, ценой и необязательным штрихкодом.
- Обновление полей, рост `version`, сохранение `created_at`.
- Логическое удаление: товар исчезает из списка, карточки и поиска.
- Повторное использование штрихкода после удаления.
- Уникальность активного штрихкода без учёта регистра.
- Несколько товаров без штрихкода.
- Поиск по названию и штрихкоду, без учёта регистра и лишних пробелов.
- Приоритет: точный штрихкод → точное название → префиксы → вхождение.
- Стабильная сортировка.
- Литеральные `%` и `_` в поисковом запросе.
- Каталог из 5 000 товаров: вставка и поиск.
- Валидация пустого имени, пустой/отрицательной/дробной/слишком большой цены.
- Пустой штрихкод → `NULL`, ведущие нули сохраняются.
- Сохранение после перезапуска БД.

### Сканер

- Поиск активного товара по точному коду: trim, без учёта регистра, ведущие нули, удалённые товары исключены.
- Пустой, неизвестный и слишком длинный код не находятся.
- Найденный товар формирует переход в карточку.
- Неизвестный товар формирует форму с исходным штрихкодом.
- Повторные события во время поиска не запускают второй запрос.
- После получения результата новые коды не меняют переход.
- Ошибка поиска требует явного повтора; повтор использует сохранённый код.
- Новый товар получает предзаполненный штрихкод, значение сохраняется вместе с ведущими нулями.

## Что не покрыто

- Основной сценарий на физическом телефоне **проверен пользователем**: распознавание штрихкодов, добавление товара и повторное открытие карточки.
- Проверка каждого формата EAN-13/EAN-8/UPC-A/UPC-E/Code 128/Code 39 на реальных упаковках по отдельности.
- Автофокус, слабое освещение, расстояние, блики, наклон и фронтальная камера.
- Отзыв разрешения камеры через настройки во время открытого сканера.
- Отсутствие камеры и ошибка запуска на физическом устройстве.
- Compose UI-тесты кликов и навигации (есть smoke-тест запуска и ручная проверка).
- Живой Supabase: применение миграций, JWT, Admin API, RLS в реальном проекте.
- Android-авторизация по номеру телефона и паролю, хранение сессии, выход.
- Realtime и синхронизация.
- FCM, уведомления, переход из уведомления.
- Синхронизация, офлайн-восстановление, конфликты версий.
- Release-сборка и подпись.

## Ручная проверка на эмуляторе (выполнена)

Окружение: AVD `storeprice_test`, Pixel 4, Android 15 (API 35), x86_64; эмулятор 37.2.12, графика `swiftshader_indirect`, камера `-camera-back virtualscene`. Финальный APK установлен через `adb install -r`, приложение запущено через `am start`.

### Каталог

- холодный запуск и каталог с сохранённым товаром `Milk`, штрихкод `00123`;
- добавление товара с ценой и штрихкодом, ведущие нули отображаются;
- после создания открывается карточка товара;
- дубликат активного штрихкода отклоняется с сообщением об ошибке;
- поиск по штрихкоду и по названию без учёта регистра;
- открытие карточки, редактирование цены;
- удаление с подтверждением, товар исчезает из каталога;
- сохранение данных после перезапуска приложения и повторной установки APK.

### Сканер

- кнопка в верхней панели каталога открывает экран «Сканер»;
- при входе показывается системный запрос разрешения камеры;
- после отказа отображается русский экран с объяснением, кнопками «Разрешить» и «Настройки»;
- после разрешения открывается предпросмотр CameraX, видны рамка и инструкция;
- при закрытии сканера в logcat появляются `Closing camera` и `CameraDevice.onClosed()`, то есть камера освобождается;
- возврат в каталог работает, сохранённый товар остаётся на месте.

**Не проверено:** распознавание настоящего штрихкода, переход к найденному товару и форма с предзаполненным кодом в реальном сценарии камеры. Это требует физического телефона или иного источника кадров с штрихкодом.

## Ручная проверка на физическом телефоне (выполнена пользователем)

Пользователь установил debug APK на свой телефон. Подтверждено:

- камера распознаёт штрихкоды;
- новый товар добавляется в базу через сценарий сканирования;
- повторное сканирование сохранённого товара открывает карточку.

Это закрывает основной сценарий этапа 3. Модель телефона и версия Android не зафиксированы. Отдельно **не подтверждены**: каждый формат на разных упаковках, отказ/отзыв разрешения, отсутствие камеры, автофокус, слабое освещение, блики, наклон, фронтальная камера и освобождение камеры по логам на телефоне.

### Каталог и общие сценарии

1. Первый запуск: каталог, кнопка «Добавить товар», кнопка сканера.
2. Добавить товар без штрихкода → появляется в списке.
3. Добавить товар со штрихкодом `00123` → ведущие нули отображаются.
4. Попробовать добавить второй товар с `00123` → ошибка дубликата.
5. Поиск `МОЛОКО`, затем с лишними пробелами → результаты корректны.
6. Поиск по части штрихкода → точное совпадение выше префикса.
7. Открыть карточку, изменить цену → список обновляется.
8. Удалить товар с подтверждением → исчезает из каталога и поиска.
9. Добавить товар с тем же штрихкодом после удаления → успешно.
10. Закрыть и снова открыть приложение → товары на месте.
11. Повернуть экран в форме → введённые данные не теряются.
12. Проверить тёмную тему и крупный системный шрифт.
13. Проверить ввод с экранной клавиатуры, включая действие «Готово».

### Сканер на телефоне

1. Войти в сканер при выданном разрешении → предпросмотр без чёрного экрана.
2. Отказать в разрешении → экран объяснения; «Разрешить» повторяет запрос.
3. Отказать с «Больше не спрашивать» → «Настройки» открывают экран приложения; после выдачи разрешения вернуться → камера запускается.
4. Навести на EAN-13 существующего товара → открывается его карточка. **Основной сценарий подтверждён; конкретный формат не зафиксирован.**
5. Навести на неизвестный EAN-13 → форма нового товара с заполненным кодом; сохранить. **Основной сценарий подтверждён; конкретный формат не зафиксирован.**
6. Проверить EAN-8, UPC-A, UPC-E, Code 128, Code 39 на реальных упаковках.
7. Держать один код перед камерой → не должно быть повторных переходов/поисков.
8. Уйти из сканера кнопкой закрытия и системной кнопкой «Назад» → камера освобождается, приложение не падает.
9. Свернуть приложение во время сканирования и вернуться → нет зависшего предпросмотра.
10. Проверить автофокус, слабое освещение, блики и наклон.
11. Проверить, что при отсутствии камеры показывается отдельное сообщение (эмулятор с камерой это не проверяет).

## SQL-миграции Supabase (локальная проверка)

Миграции `supabase/migrations/202611100001_schema.sql` и `202611100002_rls_and_rpc.sql` проверены на временной базе PostgreSQL 17 с заглушками `auth.users`, `auth.uid()`, `auth.role()` и ролями `anon`/`authenticated`/`service_role`. Проверено:

- профиль создаётся триггером и неактивен по умолчанию;
- неактивный и деактивированный сотрудник не читает каталог и не вызывает RPC;
- создание товара, trim названия, пустой штрихкод → `NULL`, ведущие нули;
- уникальность активного штрихкода и переиспользование после soft delete;
- рост `version`, конфликт версий, история цены, аудит;
- запрет сотруднику удалять/восстанавливать товар и менять себе роль;
- неизменяемость истории цен;
- доступ к `device_tokens` только владельцу;
- административные RPC активации и смены роли;
- аудит недоступен сотруднику.

**Не проверено:** живой Supabase, JWT-claims от Supabase Auth, Admin API, сетевые ошибки и реальные RLS-запросы через PostgREST. Это нужно сделать после создания проекта по `docs/SUPABASE_SETUP.md`.

## Производительность

Тест с 5 000 товаров подтверждает корректность выборки, но **не является замером скорости**. Точные показатели поиска и прокрутки нужно измерять на реальном устройстве. Сканирование на эмуляторе запускается медленнее и не показательно для телефона; время распознавания также нужно измерять на устройстве.
