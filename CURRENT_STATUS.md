## Что работает

### Каталог (этап 2)

- Локальный каталог товаров на Room: список, пустое состояние, загрузка.
- Добавление товара: обязательное название, целая цена в тенге, необязательный штрихкод.
- Редактирование названия, цены и штрихкода.
- Логическое удаление с подтверждением; товар исчезает из списка, карточки и поиска.
- Уникальность штрихкода среди активных товаров; пустой штрихкод сохраняется как `NULL`; ведущие нули сохраняются.
- Повторное использование штрихкода после логического удаления.
- Локальный поиск по названию и штрихкоду без учёта регистра и лишних пробелов.
- Приоритет поиска: точный штрихкод → точное название → префикс штрихкода → префикс названия → вхождение.
- Русский интерфейс на Compose Material 3, светлая и тёмная темы.
- Сохранение данных после перезапуска приложения и повторной установки APK.
- Room schema v1 экспортирована в `app/schemas/`.

### Сканер (этап 3)

- Кнопка сканера в верхней панели каталога; отдельный маршрут `scanner`.
- Запрос разрешения `CAMERA` при входе и обработка отказа: объяснение, повторный запрос и переход в настройки приложения.
- Обработка отсутствия камеры отдельным экраном.
- CameraX-предпросмотр, визуальная рамка сканирования и инструкция на русском.
- Локальное распознавание ML Kit без обязательного сервера: EAN-13, EAN-8, UPC-A, UPC-E, Code 128, Code 39, Code 93, ITF и Codabar.
- Защита от повторной обработки: первый распознанный код блокирует сессию, пока выполняется поиск или уже есть результат.
- Повтор одного и того же кода в соседних кадрах дополнительно подавляется в анализаторе.
- Поиск по точному активному штрихкоду без учёта регистра, с trim и сохранением ведущих нулей; удалённые товары не возвращаются.
- Найденный товар → карточка товара.
- Неизвестный код → форма нового товара с заполненным штрихкодом.
- Камера привязана к lifecycle экрана и освобождается при уходе; при ошибке запуска есть повтор.
- ML Kit добавляет в объединённый manifest разрешения `INTERNET` и `ACCESS_NETWORK_STATE`, но собственного сетевого кода в приложении нет; модель распознавания входит в APK.

### Проверка на физическом телефоне

Пользователь установил debug APK на свой телефон и подтвердил:

- камера распознаёт штрихкоды;
- неизвестный код позволяет добавить товар в базу;
- повторное сканирование того же товара открывает его карточку.

Не подтверждены отдельно: каждый заявленный формат на реальных упаковках, отказ/отзыв разрешения, отсутствие камеры, автофокус, слабое освещение, блики, наклон и освобождение камеры по логам на телефоне.

### Supabase, этап 4 (в работе)

- Миграция `supabase/migrations/202611100001_schema.sql`: `profiles`, `products`, `price_history`, `device_tokens`, `audit_log`, ограничения, индексы, триггеры.
- Миграция `supabase/migrations/202611100002_rls_and_rpc.sql`: RLS, права ролей, серверные RPC `create_product`, `update_product`, `soft_delete_product`, `restore_product`, `admin_set_employee_active`, `admin_set_employee_role`.
- Штрихкод уникален среди активных товаров через частичный уникальный индекс по `lower(barcode)`; пустой штрихкод нормализуется в `NULL`, ведущие нули сохраняются.
- `version` увеличивается триггером; RPC проверяет ожидаемую версию и возвращает конфликт `40001`.
- История цены пишется серверным триггером атомарно с изменением товара; строки истории защищены от изменения и удаления.
- Создание, изменение, удаление и восстановление товара пишутся в `audit_log`; чтение аудита — только администратор.
- Новый пользователь Auth получает неактивный профиль `employee`; активация и роль меняются только администратором.
- Вход запланирован по номеру телефона и паролю; публичная регистрация отключена.
- Инструкция: `docs/SUPABASE_SETUP.md`.

Миграции **не применены** к живому Supabase. Android-авторизация, экран входа и подключение каталога к общей базе не реализованы.

- отсутствие чтения `audit_log` у сотрудника.

Тест выполнялся временным скриптом с очисткой базы и ролей; в репозиторий скрипт не добавлен. Живой Supabase не проверялся.

## Ограничения и риски

1. **Проверка на телефоне покрывает основной сценарий, но не полную матрицу.** Подтверждены распознавание, добавление товара и повторное открытие карточки; отдельно не проверены все форматы, автофокус, освещение, блики, отзыв разрешения, отсутствие камеры и энергопотребление.
2. **Форматы проверены конфигурацией ML Kit и основным сценарием на телефоне.** Реальное чтение каждого из EAN-13/EAN-8/UPC-A/UPC-E/Code 128/Code 39 и дополнительных форматов на разных упаковках не подтверждено по отдельности.
3. **Эмулятор медленный.** CameraX на эмуляторе запускался с задержкой и предупреждениями о виртуальной камере; это не показатель поведения телефона.
4. **Нет instrumented/Compose UI-тестов.** Клики, разрешения и навигация проверены вручную; автоматизированы unit/DB/smoke-тесты.
5. **Модель устройства не зафиксирована.** Проверка выполнена пользователем на его телефоне; точная модель и версия Android в документации не указаны.
6. **ML Kit добавляет `INTERNET`.** Кода сетевых запросов пока нет, модель встроена; для Supabase разрешение понадобится.
7. **Миграции не проверены в живом Supabase.** Локальный PostgreSQL с заглушками Auth не заменяет проверку RLS, JWT и Admin API в реальном проекте.
8. **Phone + password в Android не реализован.** Схема БД готова, но экрана входа, хранения сессии и Supabase-репозитория нет.
9. **Нет release-сборки.** `assembleRelease`, keystore и minify не настроены.
10. **Нет CI.** Remote настроен, но сборка, тесты и lint выполняются только локально.
11. **`local.properties` привязан к `/home/quanysh/android-sdk`.** На другой машине путь нужно изменить.
