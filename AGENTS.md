# StorePrice — инструкции для разработки

## Назначение проекта

StorePrice — Android-приложение для небольшого продуктового магазина: общий каталог товаров, цены в тенге, поиск, сканирование штрихкодов, история цен, офлайн-доступ, синхронизация и push-уведомления.

Основной язык интерфейса — русский. Все цены хранятся целыми числами в тенге (`BIGINT` / `Long`).

## Текущий этап

Этап 3 завершён: работает локальный каталог на Room и сканер CameraX + ML Kit — разрешение камеры, предпросмотр, форматы EAN/UPC/Code 128/Code 39 и дополнительные, поиск товара по штрихкоду, переход к карточке или форме с предзаполненным кодом. Сборка, 50 unit-тестов и lint проходят. На эмуляторе Android 15 проверены экран сканера, разрешения, предпросмотр и освобождение камеры. Пользователь проверил на физическом телефоне основной сценарий: распознавание, добавление товара и повторное открытие карточки.

**Не подтверждено отдельно:** полная матрица форматов, автофокус, освещение, отзыв разрешения, отсутствие камеры и логи освобождения камеры на телефоне. Это дополнительные ручные проверки, основной сценарий этапа 3 закрыт.

**Следующий этап — 4:** Supabase, авторизация, RLS и общий каталог. Для начала нужен проект Supabase (URL и публичный anon/publishable key) и решение по авторизации сотрудников. Секреты в APK и Git не попадают.

## Окружение

Инструменты установлены локально для пользователя, без `sudo`, Android Studio и изменений системы:

```bash
source scripts/android-env.sh
```

- JDK: Temurin 17.0.21+9, `~/.local/opt/jdk-17.0.21+9`
- Android SDK: `~/android-sdk` (`platforms;android-35`, `build-tools;35.0.0`, `platform-tools`)
- Эмулятор: 37.2.12, system image `system-images;android-35;default;x86_64`, AVD `storeprice_test` (Android 15)
- Gradle: 8.9, `~/.local/opt/gradle-8.9`; в проекте используется Gradle Wrapper 8.9
- `local.properties` содержит `sdk.dir` и не коммитится
- `/dev/kvm` доступен пользователю через ACL; эмулятор запускается с программной графикой

## Обязательные команды

```bash
source scripts/android-env.sh
./gradlew assembleDebug
./gradlew testDebugUnitTest
./gradlew lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

Не заявлять об успешной сборке, установке или тесте без фактической проверки файла/вывода команды.

## Правила разработки

1. **Не перескакивать этапы.** Не начинать Room, сканер, Supabase, FCM, пока предыдущий этап не собран и не проверен.
2. **Не перезаписывать пользовательские файлы.** Перед крупными изменениями проверять `git status` и содержимое каталогов.
3. **Секреты не попадают в Git и APK.** `SUPABASE_SERVICE_ROLE_KEY`, Firebase service account и любые приватные ключи запрещены в Android-модуле. Публичный anon/publishable key — только через локальную конфигурацию.
4. **Room — источник данных для UI.** Экраны и поиск читают локальную базу; сеть обновляет Room, а не UI напрямую.
5. **Сервер — источник правды для прав и истории.** RLS и серверные функции обязательны; клиентские проверки роли недостаточны.
6. **Схема Room версионируется.** Схемы лежат в `app/schemas/`; после изменения сущностей — новая версия БД и миграция. Не использовать destructive fallback.
7. **Штрихкод уникален среди активных товаров.** Пустой штрихкод — `NULL`; ведущие нули сохранять. Удаление — логическое, чтобы штрихкод можно было переиспользовать.
8. **UI на русском.** Строки — в `res/values/strings.xml`, без «рыбных» товаров в рабочей базе.
9. **Цены — целые тенге.** Не использовать `Double` для денег.
10. **Минимальные зависимости.** Добавлять библиотеку только под конкретную задачу этапа, проверяя совместимость версий.
11. **Документация — часть результата.** После этапа обновлять `CURRENT_STATUS.md` и, при необходимости, `ARCHITECTURE.md`/`ROADMAP.md`/`docs/TESTING.md`.
12. **Не выдавать заглушки за реализацию.** В отчёте явно разделять: работает / не проверено / не реализовано.

## Стиль кода

- Kotlin, Gradle Kotlin DSL, version catalog (`gradle/libs.versions.toml`).
- MVVM: `ui` → `ViewModel` → `Repository` → `Room`/`Supabase`.
- Coroutines и `Flow`; UI-состояние иммутабельное.
- Пакеты по слоям внутри `com.storeprice.app` (`core`, `data`, `domain`, `ui`).
- Публичные функции и нетривиальная логика — с KDoc; бизнес-правила покрывать unit-тестами.
