# Требования StorePrice

Полное техническое задание: [`docs/REQUIREMENTS.md`](docs/REQUIREMENTS.md). Этот файл — краткая точка входа; при расхождении приоритет у полного ТЗ.

## Продукт

Android-приложение для продуктового магазина: совместный каталог товаров, цены в тенге, поиск по названию и штрихкоду, сканирование камерой, история цен, офлайн-просмотр, синхронизация между сотрудниками, роли и push-уведомления.

## Текущая граница работ

**Этапы 2 и 3 реализованы.** Этап 3 (сканирование) проверен на физическом телефоне в основном сценарии: распознавание штрихкодов, добавление нового товара и повторное открытие карточки. Детальная матрица форматов и edge-case-сценарии отдельно не подтверждены.

**Этап 4 начат.** Подготовлены SQL-миграции Supabase: `products`, `profiles`, `price_history`, `device_tokens`, `audit_log`, ограничения, индексы, RLS и серверные RPC для записи с проверкой версии. Вход планируется по номеру телефона и паролю. Миграции проверены на локальном PostgreSQL со заглушками Supabase Auth, но **не применены к живому проекту**; Android-клиент и экран входа ещё не реализованы.

Реализовано:

- Room-база `products`, схема v1 в `app/schemas/`;
- добавление, редактирование и логическое удаление товаров;
- поиск по названию и штрихкоду без учёта регистра, с приоритетом точных совпадений;
- валидация названия, цены и штрихкода, уникальность штрихкода среди активных товаров;
- экраны каталога, карточки товара и формы добавления/редактирования на Compose;
- сканер CameraX + ML Kit с разрешением камеры, обработкой отказа и отсутствия камеры;
- форматы EAN-13, EAN-8, UPC-A, UPC-E, Code 128, Code 39, Code 93, ITF, Codabar;
- защита от повторного срабатывания и остановка камеры при уходе с экрана;
- поиск активного товара по точному штрихкоду; найденный товар открывает карточку, неизвестный код — форму с заполненным штрихкодом;
- 50 unit/DB/смоук-тестов, сборка debug APK.

Не входит в текущий этап и не начато:

- живой проект Supabase, Android-авторизация, экран входа, Realtime;
- подключение Android-каталога к Supabase и синхронизация;
- FCM и push-уведомления;
- офлайн-обновление;
- UI истории цен, управления сотрудниками, импорт/экспорт;
- выпуск подписанного release APK.

## Критерии приёмки этапа 2

1. `./gradlew assembleDebug` завершается успешно, APK существует.
2. Товар создаётся, редактируется и логически удаляется; данные сохраняются после перезапуска БД.
3. Поиск работает локально по названию и штрихкоду, без учёта регистра и лишних пробелов.
4. Точный штрихкод и точное название имеют приоритет; сортировка стабильна.
5. Пустой штрихкод сохраняется как `NULL`, ведущие нули не теряются, дубликат активного штрихкода отклоняется.
6. Каталог из 5 000 товаров обрабатывается в тесте.
7. `./gradlew testDebugUnitTest` и `./gradlew lintDebug` проходят без ошибок.
8. `CURRENT_STATUS.md` содержит фактические результаты и ограничения.

Критерии этапа 2 выполнены на эмуляторе. На физическом телефоне подтверждены добавление товара через сканер и повторное открытие его карточки; полный набор CRUD и поиска на телефоне отдельно не проверялся.

## Критерии приёмки этапа 3

1. Сканер открывается из каталога, запрашивает разрешение и объясняет отказ/отсутствие камеры.
2. Поддерживаются заявленные форматы; распознавание выполняется локально.
3. Повторный код не запускает повторную обработку в одной сессии.
4. Найденный активный товар открывает карточку; неизвестный код открывает форму с заполненным штрихкодом.
5. Камера освобождается при уходе с экрана.
6. `./gradlew testDebugUnitTest` и `./gradlew lintDebug` проходят без ошибок, APK собирается.
7. `CURRENT_STATUS.md` честно разделяет проверенное, непроверенное и нереализованное.

Пункты 1, 3, 4 и 5 проверены unit-тестами и/или вручную на эмуляторе. Пункт 2 подтверждён на физическом телефоне: пользователь отсканировал штрихкоды, добавил товар и повторно открыл его карточку. Полная проверка каждого формата на разных упаковках, автофокус, освещение и поведение при отзыве разрешения остаются дополнительными ручными проверками.

## Нефункциональные требования (для будущих этапов)

- Русский интерфейс, Material 3.
- Цены — целые тенге, без потери точности.
- Локальный каталог минимум на 5 000 товаров.
- Поиск не блокирует главный поток, результаты обновляются на каждый ввод.
- Офлайн: просмотр и поиск последней синхронизированной копии.
- Секреты сервера не попадают в APK.
- Все критические проверки прав и запись истории — на сервере.
- Воспроизводимая сборка через Gradle Wrapper.
